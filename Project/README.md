# AI-Powered Intelligent Hiring Assistant

An end-to-end system that evaluates candidate resumes against job descriptions
using ML/DL scoring, explains the result with a **RAG (Retrieval-Augmented
Generation)** pipeline grounded in a real resume corpus, and exposes it all
through a conversational interface built with an **agentic** control loop.

Built on your `resumes_dataset.jsonl` — 3,500 resumes across 36 job
categories (Java Developer, Python Developer, Data Science, DevOps, etc.).

## Architecture

```
resumes_dataset.jsonl
        │
        ▼
┌───────────────────┐
│ 1. Preprocessing   │  clean noisy text, extract skills, extract years of exp
│ (src/preprocess.py)│
└─────────┬──────────┘
          ▼
┌───────────────────┐
│ 2. Embeddings (ML) │  TF-IDF → Truncated SVD (LSA), 256-dim, L2-normalized
│ (src/features.py)  │
└─────────┬──────────┘
          ▼
┌────────────────────────────┐   ┌───────────────────────────┐
│ 3. DL Classifier             │   │ 4. Retriever (RAG index)   │
│    MLP neural net predicts   │   │    Nearest-neighbor search │
│    job category + confidence │   │    over the resume corpus  │
│ (src/classifier.py)          │   │ (src/retriever.py)         │
└───────────────┬───────────────┘   └────────────┬──────────────┘
                └───────────────┬───────────────────┘
                                 ▼
                  ┌──────────────────────────────┐
                  │ 5. Scoring + Explainable      │  skill overlap +
                  │    Feedback (RAG generation)  │  semantic similarity +
                  │ (src/feedback.py)             │  retrieved evidence →
                  └───────────────┬────────────────┘  grounded LLM prompt
                                  ▼
                  ┌──────────────────────────────┐
                  │ 6. Agent orchestration        │  decides: ask for input /
                  │ (src/agent.py)                │  evaluate / retrieve /
                  └───────────────┬────────────────┘  answer question
                                  ▼
                  ┌──────────────────────────────┐
                  │ 7. Conversational UI           │  Streamlit chat app
                  │ (app.py)                       │
                  └────────────────────────────────┘
```

**Why this design:**
- **ML** = TF-IDF + LSA embeddings (fast, no external downloads, fully
  reproducible from your data).
- **DL** = a feed-forward neural network (MLP, trained with backprop/Adam)
  classifies resumes into 1 of 36 categories with **88% validation accuracy**.
- **RAG** = every piece of generated feedback is grounded in retrieved,
  real evidence (similar resumes, category-level common skills) — not
  invented by the LLM.
- **Agentic** = `HiringAssistantAgent` maintains conversation state and
  decides at each turn whether it needs more input, needs to run the
  evaluation, or can answer a follow-up question — rather than being a
  single fixed prompt.
- **LLM** = Claude (Anthropic API) turns the structured evidence into
  fluent, honest, candidate-facing feedback. The system runs **fully
  offline** without an API key too (rule-based fallback), so you can
  demo it immediately and upgrade to live Claude generation any time.

## Project structure

```
hiring_assistant/
├── data/resumes_dataset.jsonl     # your dataset
├── src/
│   ├── preprocess.py              # cleaning + skill/years extraction
│   ├── features.py                # TF-IDF + LSA embedder (ML)
│   ├── classifier.py              # MLP neural classifier (DL)
│   ├── retriever.py                # nearest-neighbor RAG retriever
│   ├── llm.py                      # Claude API wrapper + offline fallback
│   ├── feedback.py                 # scoring + grounded feedback generation
│   └── agent.py                    # agentic orchestration layer
├── train.py                        # builds all artifacts from the dataset
├── app.py                          # Streamlit conversational UI
├── tests/test_pipeline.py          # end-to-end smoke test (no UI needed)
├── artifacts/                      # generated by train.py (embeddings, models)
└── requirements.txt
```

## Setup

```bash
cd hiring_assistant
pip install -r requirements.txt

# 1. Build the pipeline (preprocess data, train embedder + classifier, build RAG index)
python train.py

# 2. Sanity-check the whole pipeline without the UI
python tests/test_pipeline.py

# 3. Launch the conversational app
streamlit run app.py
```

`train.py` takes well under a minute on the full 3,500-resume dataset and
prints validation accuracy for the classifier as it goes.

## Using live Claude-generated feedback

By default (no API key) the app uses a deterministic, still-grounded
template generator so everything works out of the box. To get natural,
LLM-written feedback and chat:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
streamlit run app.py
```

or paste the key into the sidebar field in the app. The model used is
`claude-sonnet-4-6`.

## How scoring works

```
overall_score = 100 * (0.45 * semantic_similarity + 0.55 * skill_overlap)
```

- `semantic_similarity`: cosine similarity between the resume's and job
  description's embeddings (captures context/phrasing, not just keywords).
- `skill_overlap`: fraction of the job description's required skills
  (from a curated skills taxonomy) found in the resume.
- The DL classifier's predicted category + confidence is reported
  separately and used to pull category-specific RAG evidence (e.g. "the
  most common skills among strong Python Developer resumes in this
  corpus are X, Y, Z").

Every number the LLM is given is computed upstream — the prompt
explicitly instructs it not to invent facts, which is what makes the
feedback *explainable* rather than a black box.

## Extending this

- **Bigger corpus / production retrieval**: swap `sklearn.NearestNeighbors`
  in `retriever.py` for FAISS or a vector DB (pgvector, Pinecone, Weaviate)
  — the `.query()` interface stays the same.
- **Better embeddings**: swap `Embedder` in `features.py` for a hosted
  embedding model (OpenAI, Voyage, or a local sentence-transformers model)
  — everything downstream only depends on `transform(list[str]) -> np.ndarray`.
- **Real DL model**: swap `CategoryClassifier` in `classifier.py`
  (currently sklearn's MLP) for a PyTorch/TensorFlow model with the same
  `fit`/`predict_proba` interface.
- **Multi-agent**: split `HiringAssistantAgent` into specialized
  sub-agents (Screener, Coach, Interviewer) that hand off to each other —
  the state/tool pattern already supports this.
- **Resume upload**: add a PDF/DOCX parser (e.g. `pdfplumber`,
  `python-docx`) in front of `agent.set_resume()` so candidates can
  upload files instead of pasting text.
